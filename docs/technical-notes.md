# 技术说明（原 README 详细内容）

本页保存各模块的实现细节与历次核验记录，供开发与排查参考；使用方法见 [README](../README.md)。

## 操作体验与运行逻辑改进

- 应用选项显示中文名称与说明，战斗和空洞挑战配置从本地模板生成下拉。
- 「结束后」使用下拉选择，选择关机时才显示关机延迟。
- 日常勾选正确映射到应用 ID，组配置与应用选项统一批量保存。
- JSON 编辑允许临时不完整的草稿；运行前统一校验，错误时提示并停止任务。
- 自动战斗与闪避助手互斥；独立应用启动时停用常驻助手，避免输入冲突。
- 战斗配置与前台/后台模式切换在下一次识别时生效，截图间隔控制实际识别频率。
- 终结技开关可在运行中调整；结算停止会停用助手，需手动启用下一场。
- 暂停、恢复与停止按钮同步到底层应用；手动停止不执行结束后动作。
- 框架截图统一到 1920×1080；切换输入设备先释放按键，停止可中断键鼠长按。

上述行为已有离线回归测试和 Qt 控件验证；游戏识别效果与后台手柄输入仍需实机验证。

## 环境要求

- Windows 10 21H2 64 位及以上
- Python 3.12
- 《绝区零》PC 客户端，16:9 分辨率（最低 1280x720）
- 后台模式需安装 [ViGEm Bus 驱动](https://github.com/nefarius/ViGEmBus/releases)

## 快速开始

```powershell
# 1. 创建虚拟环境（uv 或 venv）
uv venv --python 3.12 .venv
.venv\Scripts\activate

# 2. 安装依赖
pip install --no-deps -r requirements.lock.txt

# 3. 发布包已包含闪避与 OCR 模型；源码模型缺失时可用此命令补齐
python tools\download_models.py

# 4. 运行（需要游戏窗口；调试模式会在画面上绘制识别框）
python main.py        # 正常运行
python main_debug.py  # 调试模式
```

首次启动后：
1. 首次运行会在后台只读扫描 Windows 注册表，发现唯一有效客户端后保存游戏路径；未发现或有多个客户端时，在「全局设置 → 游戏安装设置 → 游戏路径」选择 `ZenlessZoneZero.exe`。已有路径不被自动发现覆盖。游戏启动后选择游戏窗口。
2. 运行「诊断」任务确认截图/OCR/输入链路
3. 勾选「⚔️ 自动战斗」触发器，进入战斗即可由引擎接管
4. 勾选「💬 自动跳过对话」触发器，持续识别当前剧情、对话和选项

自动战斗助手持续识别画面，确认敌人血条、持续出现的红色敌人方向箭头、连携界面或新的攻击预警后才执行动作。
只有普攻按钮可见时不会接管；确认敌人后持续战斗 10 秒，期间不重复检查敌人是否消失。
10 秒结束后释放按键并重新检测：仍有敌人则开始下一轮 10 秒，没有敌人则等待。
战斗期间仍更新角色、技能与闪避状态；攻击预警不会延长本轮时间。
攻击按钮消失时跳过敌人、方向箭头、闪光、角色和目标检测，取消当前指令并释放按键；
动画结束后在原有期限内恢复，不额外增加10秒。连携计时条与头像单独确认，只允许连携按键。
低血量和血条变灰时结合面板边框与失衡条识别，不使用血条旁属性图标的颜色判定。
箭头需要红色三角形、黑色边框、向外指向和连续画面确认；当前录像没有可确认的箭头正样本，仍需实机样本校准。
截图中断、切走前台键鼠窗口、暂停或关闭助手时提前取消动作并释放按键。
任务信息中会显示「等待敌人」「战斗中」等状态。

连携入口同时检查左右头像，支持左侧邦布、右侧角色的组合；选人、快速支援方向和技能指令沿用一条龙模板。
未识别角色自动使用通用操作：就绪时释放特殊技和终结技，并限制重复释放，期间用普攻衔接；
原模板没有匹配操作时也会回退到通用操作。战斗配置可直接选择「通用操作」，不依赖角色专属连招。
默认开启「优先实时闪避」，黄光优先触发支援弹刀（默认空格，后台手柄RB/R1）再衔接普攻；红光、声音提示触发闪避反击。

16:9游戏客户区自动适配1280×720、1600×900、1920×1080、2560×1440、3840×2160等分辨率。截图按实际像素尺寸换算识别区域，点击坐标按当前客户区反向换算，窗口移动或调整大小后自动更新。助手任务信息显示当前窗口分辨率，诊断同时记录原始尺寸与识别尺寸。无需手动修改模板坐标。

编队存在未识别头像时仍搜索完整角色表，但优先匹配已识别的编队成员，避免连携窗口识别超时。闪光短暂漏检一帧不会再次触发同一次弹刀或闪避，真正间隔的攻击仍可实时响应。
没有可切换队友、识别到切人冷却或支援不可用时，黄光回退为闪避。关闭该选项后使用原角色模板的黄光支援、闪避与无敌动作保护。
同一红光的反应状态在实际闪避后消耗，避免反复闪避；角色的专属资源、蓄力和复杂连招仍由专属模板实现。
关闭「自动终结技」会阻止模板中的终结技点按或长按，已有按键仍可释放。
输入被暂停时不再预测连携/支援切人或发布已执行状态，避免恢复后按错误的前台角色出招。
技能闭环已用真实战斗模板、头像素材和替身输入离线验证；实机识别与技能释放效果仍需校准。

截图和控制器共用界面选中的窗口句柄；游戏重启或更换窗口后重新绑定，避免已选窗口却提示未找到。
勾选常驻助手不会将游戏切到前台。前台模式在切走时停止输入、释放按键，返回游戏后继续检测。
后台模式下自动战斗/闪避使用虚拟手柄，不切换前台、不移动物理鼠标，需要 vgamepad 与 ViGEmBus。
后台输入是否被游戏接受仍需实测；驱动缺失或初始化失败会停止助手，不会改用前台键鼠。
游戏只响应最近使用的输入设备：自己用键鼠玩、同时开闪避/自动战斗时，请选前台模式。
截图在游戏后台继续更新；窗口最小化、截图中断时仍停止动作，不能仅靠后台输入绕过画面不可用的问题。

闪避助手持续检测红光、黄光与声音提示，无新事件时不发送按键，也不自动锁定或转视角。
持续闪光去重，超过 250ms 的识别结果丢弃；每次新事件只开放最长 0.8 秒的响应窗口，
用于所选配置的闪避、格挡及后续反击，随后释放输入。暂停、关闭助手或切换配置会使旧动作失效。
这套画面识别已用仓库截图和离线替身输入测试；游戏版本、画面特效及遮挡可能影响命中率，仍需实机验证。

自动跳过对话默认每 0.1 秒检测一次，只有当前画面确认出现剧情按钮、对话内容或对话选项时才点击。
可选择「跳过剧情」「自动点击」「等待剧情自动播放」，以及对话选项的第一个/最后一个。
点击间隔只限制已识别动作的频率，不会按固定时间盲点；黑屏、对话消失和未知画面保持等待。
跳过确认须识别到明确的跳过提示，避免误点其它确认框；前台模式下游戏切走时暂停。
此助手可与战斗/闪避助手同时勾选，独立任务运行期间等待，关闭或暂停后丢弃正在识别的结果。
切换窗口、窗口关闭或识别耗时超过 0.5 秒时也丢弃结果；过期时间包括截图耗时。
后台模式下，对话点击仅向选中窗口发送带坐标的消息，不激活窗口或移动物理鼠标。
后台消息可能被游戏忽略，此时需切回前台；不会自动抢回前台作为补救。

这三项常驻助手不需要用户添加其它 YOLO：敌人入口依靠血条面板及连携画面的特征，
闪避使用发布包内的闪光分类模型与声音模板，对话使用发布包内的 OCR 模型。
迷失之地与枯萎之都的导航模型独立于常驻助手，首次运行对应任务时会尝试自动下载；
离线安装如尚无这些模型，对应任务无法完成导航。源码可使用 `python tools/download_models.py --all` 补齐。
界面「游戏按键设置」现在同步到控制器，下次任务启动生效；首次接入时保留已有账号的非默认键位。

任务参数使用中文标题；角色、任务、游历时长、价格等级、路线处理方式和模板使用选择控件。
兑换优先级从上到下选择物品，选择“不兑换”移除该项；已有配置的存储键和值保持兼容。

迷失之地选择「任务名称：矩阵行动」，将「矩阵行动编队方式」设为「自定义编队」，
然后按角色一、二、三的顺序选择主战角色（至少一个，可留空其它槽位）。
程序先校验角色配置与识别模板，再清空原主战队伍、逐个翻页选人并核对编队顺序。
角色重复、未解锁、模板缺失或画面校验失败时停止，避免用错误编队开始挑战。
协战角色仍按原来的 UP/满级角色逻辑选择；「沿用挑战配置」继续使用原有编队设置。
自定义队伍使用挑战配置中的战斗模板，不会改写共享挑战模板；选人流程已离线测试，仍需实机校准。

## 画面与日志诊断

在侧边栏「调试」中展开「🛠️ 画面与日志诊断」，选择「截图」「视频」或「截图和视频」，点击「开始录制」。
已有任务运行时立即观察该任务的画面；未运行时按 F9 开始采集，再运行需要排查的副本或助手。
默认不限时（录制时长为0），每秒一张截图和10帧视频；旧版配置升级为不限时。也可填写至少5秒的定时长度。
点击「暂停录制」停止保存画面、事件和用户输入，并冻结计时；按钮变为「继续录制」，恢复后接着记录同一轮。
点击「停止录制」结束并保存ZIP；选择定时录制时，到时自动保存。暂停冻结录制计时，保存后可开始新一轮录制。
录制暂停独立于 F9 游戏任务暂停，不影响副本脚本或助手运行。
诊断不切换游戏输入方式，也不发送游戏操作；可以与副本脚本和常驻助手一起运行。

结果保存在程序目录的 `debug/diagnostics/日期时间/`，同级 ZIP 包含：

- `frames/`：游戏截图（遮挡 UID），`frames.jsonl`：截图时间、辅助敌人特征、窗口与任务状态。
- `video.mp4`（编码器不支持时为 AVI）：1280×720 视频，`video-timeline.jsonl` 记录每一帧的时间。
- `events.jsonl`：敌人检测、战斗启动来源、副本节点、技能条件、闪避与对话识别，以及输入调用。
- `user-input.jsonl`：用户在游戏前台时的键鼠按下、释放、重复按键、点击、移动及滚轮，与视频使用同一时间线。
- `logs/`：软件及战斗引擎日志的开始、结束片段；`session.json`：停止原因、错误和丢弃数量。

截图、视频和事件使用同一 `elapsed` 秒时间线，不含录制暂停时间；`wall_elapsed` 和真实时间戳保留包含暂停的实际经过时间。
暂停与恢复写入独立事件。视频显示采集延迟；游戏截图中断超过两秒时标记
`NO FRESH GAME FRAME`。录制只保存游戏窗口，不录制音频。
辅助血条、准星特征可能误判，输入调用记录也不代表游戏已接受操作；需要结合画面判断。
单次最多保留300张独立截图，视频持续录制，大视频在约1GB时自动分段；写入失败不会中断游戏任务，程序重启后不会自动恢复录制。

侧边栏「一条龙日常」可勾选应用、上移或下移编排执行顺序，并点击「编辑」修改每个应用的设置。
体力刷本使用结构化计划表单，可逐条填写副本类别、类型、名称、等级、次数、卡片数量、战斗模板和预备编队；普通计划与双倍奖励计划分别保存，执行计数由引擎维护。
「截图方式」页的交互方式是唯一的输入开关，只有「后台模式」「前台模式」两项；一条龙、应用任务和全部常驻助手（自动战斗、闪避、对话、委托助手）都跟随它，由本程序的控制器执行（不使用 ok-script 自带的点击实现）：
「后台模式」使用虚拟手柄（菜单配合窗口消息），不抢前台、不移动鼠标，需已安装 ViGEmBus 驱动；游戏窗口可以被其他窗口遮挡或放在后台，但不能最小化（最小化后游戏不再出画面，连续 12 秒取不到画面会停止输入）；驱动缺失时任务停止并提示，不会改用前台。「前台模式」用键鼠操作，运行时切到游戏前台，切走时助手暂停。
原设置「任务后台操作」、各助手的「后台模式」「后台时暂停」「游戏在后台时暂停」已移除；保存过已移除选项（窗口消息后台、ForegroundPostMessage、PyDirect）的配置按「后台模式」运行，不会接管鼠标。
框架内置日志现在同时显示一条龙节点执行、重试与结果，以及战斗开始、实时支援、对话操作和录制分段。
「记录用户输入」默认开启，仅在所选游戏窗口处于前台时记录，鼠标事件还需位于游戏客户区。
切到其它窗口后暂停用户输入记录，录制结束或退出程序时停止监听，不拦截用户操作。
用户输入、程序的 `input_call` 和系统标记的 `observed_injected_input` 分开记录；
合成输入可能来自本程序或其它自动化，不能直接当作用户手动操作。当前用户输入记录支持键盘和鼠标。

2026-10-02 的诊断修正了框架 BGR 帧与战斗引擎 RGB 帧之间的颜色转换。
常驻战斗助手现在依据小怪血条面板（含空失衡条）或连携界面触发，圆形目标标记不能单独触发战斗；
识别到敌人后仍按配置约定持续战斗 10 秒，再重新检测。克拉蕾的红光/声音反击先发送闪避，再接普攻。
血条判定使用生命条与失衡条的阶梯边框，支持远处、低血量和半透明面板，完全不读取附近属性图标。
连携入口支持粉红/红色倒计时和即将耗尽的计时条。未收录角色保留实际队伍位置，
在战斗接管期限内使用基础普攻；已有角色继续使用原技能模板，未收录角色的专属技能尚需补充模板。
诊断事件新增 `enemy_panel`（面板位置及匹配置信度）；运行快照包含队伍槽位、实际模型执行设备和推理耗时。

## GPU 识别

默认将闪避分类模型、YOLO和OCR交给GPU。设置页「识别计算设置」可选择「GPU优先」或「CPU」，修改后重启程序生效。
GPU优先尝试CUDA，其次使用DirectML；DirectML会选择显存最多的硬件适配器，并串行调度模型调用。
初始化或推理失败时自动回退CPU，实际后端和回退原因会写入日志及诊断画面的 `runtime.recognition`。
1440P/4K画面的缩放和颜色转换通过OpenCL交给GPU；血条、头像等小区域模板和声音识别仍使用CPU。实际画面处理后端见实时状态 `image_processing`，GPU不可用时回退CPU。
CPU辅助计算限制为2线程并关闭推理空转；设置页的「识别帧率上限」默认30，可选20～60。调低帧率能进一步降低CPU压力；此设置不限制调试录像帧率。
连续实时监视使用 `/frame.jpg`，单次精确截图使用 `/frame.png`；监视画面最多每秒更新10次，同一帧复用编码，避免调试开销拖慢战斗识别。
OCR初次推理可能需要编译GPU图，后续相同形状的调用会更快。

2026-10-08 CPU优化：血条检测在同一帧内复用轮廓，最佳模板匹配直接选择最高分，
调试页隐藏或窗口最小化时跳过预览编解码，并移除截图编码前的重复1080P缩放。
后台监控、HTTP截图、识别帧率、阈值、角色候选及模板优先级保持不变；重新显示调试页后恢复最新预览。
26张本地截图的血条/方向箭头检测返回值与修改前一致，PNG/JPEG输出字节一致；
同机回放血条检测CPU耗时约减少7.7%，密集命中的最佳匹配样例约减少86%。
以上为离线局部路径对比，不代表整场战斗CPU降幅；游戏内总占用仍需同场景实测。

战斗检测现在对每种识别最多保留一个未完成任务：检测较慢时跳过追加，完成后使用新画面，避免旧截图排队。
NumPy/SciPy 的 BLAS 池与启动时的 OpenMP 池限制为2线程；支持的 OpenMP 运行库采用被动等待。
