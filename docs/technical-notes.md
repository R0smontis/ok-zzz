## 目录结构与架构分层

`ok-zzz` 在 `ok-script` 桌面框架之上桥接移植自 `ZenlessZoneZero-OneDragon` 的游戏画面识别、战斗引擎与日常操作流，并针对后台虚拟手柄模式单独实现了逐帧焦点核验导航层。

```text
main.py                # 入口：GUI、--check-package、--live-client、--live-debug
src/
  config.py            # ok-script 应用配置与版本号单源
  globals.py           # my_app 全局单例（线程安全桥接 ok-script 与 ZContext）
  tasks/               # 任务与界面（一条龙日常、应用任务、常驻触发助手、诊断、调试页）
  controls/            # 窗口输入投递、WGC/BitBlt 截图兼容与冻结检测、后台策略、物理输入观察
  navigation/          # 手柄后台导航：公共焦点/OCR 工具（common）、弹窗（popups）、对话（dialogue）、菜单/地图/随便观
  live/                # 本机实时调试：回环服务（service）、运行时桥接（runtime）、标准库客户端（client）
  runtime/             # 帧归一化与 UID 遮挡、GPU/ONNX 推理与 OCR、线程限制与阶段超时、启动兼容
  diagnostics/         # 画面与日志录制（recorder）、阶段超时现场保存及离线自检（package_check）
  zzz_od/              # 游戏业务逻辑（移植自一条龙）
    application/       #   各应用（一条龙汇总、日常、体力计划、恶名狩猎、迷失之地、枯萎之都等）
    auto_battle/       #   战斗引擎（DSL 条件场景、角色状态检查、原子操作、闪光与音频闪避）
    operation/         #   登录、传送、快捷手册、恢复电量、返回普通大世界等通用节点
    controller/        #   控制器（键鼠、窗口消息、Xbox/DS4 虚拟手柄）
    context/ config/   #   ZContext 总装配；键位、模型与战斗助手配置
  onedragon/           # 一条龙底层框架子集（画面区域/模板匹配/CV 流水线缓存/条件引擎）
assets/  config/       # 画面 YAML、模板图、内置 ONNX 模型、战斗 DSL 配置
tests/                 # 隔离运行目录的离线回归与仓库卫生测试；fixtures/ 为实机截图
tools/                 # 模型下载、任务选项生成器（gen_app_tasks.py）、实时调试入口、launcher/ 启动器构建补丁、port/ 移植脚本
deploy/                # 可选：手工 PyInstaller/NSIS 独立打包配置（正式发布走 PyAppify）
```

- **资产与许可来源**：`tools/port/fetch_onedragon_assets.py` 用于从上游一条龙仓库拉取画面定义、战斗配置与模板资产；移植范围与第三方组件许可详见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。
- **运行期本地目录（不入库）**：`config/<两位编号>/`（各账号实例配置与运行记录）、`config/model.yml`、`config/one_dragon.yml`、`config/redemption_codes.yml`、`configs/`、`logs/`、`.log/`、`cache/`、`screenshots/`、`debug/`、`build/`、`dist/`。

## 窗口绑定、分辨率与截图链路

- **环境基线**：Windows 10 21H2 64 位及以上；《绝区零》PC 客户端 16:9 分辨率（最低 `1280×720`，支持 `1600×900`、`1920×1080`、`2560×1440`、`3840×2160` 等），需关闭 HDR 与画面滤镜。
- **游戏路径发现**：首次运行后台只读扫描 Windows 注册表，仅在发现唯一有效客户端时保存 `ZenlessZoneZero.exe` 路径，不覆盖用户已有设置；未发现或存在多个客户端时在「全局设置 → 游戏安装设置 → 游戏路径」手动指定。
- **窗口句柄与启动校验**：截图与控制器共用界面选中的窗口句柄，游戏重启或换句柄后自动重绑。由程序启动游戏时，等待窗口同时满足存在、可见、非最小化且客户区达到 `supported_resolution.min_size`，句柄或尺寸稳定后才交给截图后端，避免隐藏占位小窗触发 WGC 报错。带边框窗口若超出显示器边界过多，会被 `ok-script` 窗口位置检查暂停执行。
- **逻辑分辨率归一化**：框架截图统一缩放到 `1920×1080` 逻辑空间识别（原地遮挡右下角 UID 区域），点击坐标反向映射回当前真实客户区，窗口移动或改尺寸后自动更新，无需手改模板坐标。
- **WGC / BitBlt 兼容与安全重建**：
  - Windows 10 2004 及以上支持 Windows Graphics Capture（WGC；低于 Build 20348 的旧系统保留黄色捕获边框）。
  - 窗口尺寸变化时在捕获锁外关闭旧目标，回调线程只记录新 `ContentSize` 并交由取帧请求线程重建帧池，避免跨 COM 线程异常与 `Release` 死锁。
  - WGC 与 BitBlt 拒绝全黑画面。采样亮点过少时复核完整颜色通道，避免丢掉仅有少量字幕的黑幕。运行中选中窗口捕获失败时停止输入，不自动改用另一套截图器。
  - WGC 的同一可见窗口连续 15 秒没有有效帧（包括全黑帧和取帧超时）时，在取帧线程重建会话；收到有效帧后清零计时。无效帧不会用于识别或点击。
- **15 秒冻结画面拦截**：`TaskExecutor.next_frame` 与实时监控 `GameRuntime.capture` 共用可重入锁与采样检测。画面连续 15 秒完全不变（如窗口被最小化或 WGC 会话静默卡住）时，每次冻结尝试重建一次 WGC，并在画面内容真正变化前拒绝向任务、常驻助手、预览和录制发布旧帧，同时停止当前助手和战斗输入。

## 交互模式与输入投递

「截图方式」页的交互方式控制一条龙、独立应用和战斗／闪避助手。剧情处理是例外：无论全局选择什么模式，均使用前台键鼠输入，不更改其他任务的控制器配置。

| 模式 | 输入通道 | 窗口与焦点行为 | 依赖与回退原则 |
| --- | --- | --- | --- |
| **后台模式**（默认） | 虚拟手柄（Xbox / DS4）+ 必要的后台窗口消息 | 不抢前台、不移动系统光标；游戏窗口可被遮挡，但**不能最小化** | 需安装 [ViGEmBus 驱动](https://github.com/nefarius/ViGEmBus/releases)；驱动缺失或初始化失败直接停止并提示，绝不静默改用前台键鼠 |
| **前台模式** | 键鼠输入（物理光标与键盘事件） | 任务启动时切到游戏前台；切走游戏窗口时常驻助手暂停并释放按键 | 无需虚拟手柄驱动；边用键鼠手动游玩边开闪避/自动战斗时应选此模式 |

- **输入设备切换消抖**：游戏每次只响应最近使用的输入设备；若此前停在键鼠模式，收到的第一下手柄按键只切换 UI 按键提示而不触发功能。后台模式每次开始运行时，先将右摇杆等量上推再下推（镜头净位移为零），主动把游戏切入手柄模式。
- **代际取消与按键释放**：停止、暂停、切换输入设备或更换窗口时，后台窗口消息通过代际计数作废进行中的点击/拖拽/长按；应用任务停止入口同步终止已创建的战斗上下文并释放按键。前台点击、拖拽与 ALT 组合点击均由 `finally` 保证释放（即使光标落入 PyAutoGUI 安全角触发 `FailSafeException`，也会用不移动光标的 Win32 抬起事件清理物理按键）。
- **键位与互斥**：「游戏按键设置」同步至控制器并在下次任务启动生效（首次接入保留账号已有非默认键位）。自动战斗与闪避助手互斥；独立应用运行期间自动停用常驻助手，手动停止任务不会触发「结束后（关机/休眠等）」动作。历史遗留的废弃交互项（如 `ForegroundPostMessage`、`PyDirect`、`Pynput`）在启动时迁移至后台模式。

## GPU 识别与推理调度

- **内置模型**：发布包已内置闪光分类模型、迷失之地寻路模型（`yolov26n-736-lost-void-det-20260630`）、空洞事件模型及 OCR 模型，常驻助手与迷失之地无需首次运行时联网下载。源码环境缺失模型时可运行 `python tools/download_models.py --all` 补齐。
- **推理后端路由**：「识别计算设置」可选「GPU优先」（默认）或「CPU」，修改后重启生效。GPU 优先尝试 CUDA，其次选择显存最大的硬件适配器运行 DirectML（串行调度模型调用）；初始化或推理失败自动回退 CPU，实际后端与回退原因写入日志及实时状态 `runtime.recognition`。OCR 首次运行同尺寸图可能编译 GPU 计算图，后续调用更快。
- **图像处理与线程预算**：1440P / 4K 画面的缩放与颜色转换优先通过 OpenCL 交给 GPU（状态见 `image_processing`），不可用时回退 CPU；血条、头像等小区域模板及音频相关计算运行在 CPU。启动时将 OpenCV、NumPy/SciPy BLAS 与 OpenMP 线程池限制为 2 线程并关闭推理空转。「识别帧率上限」默认 30 FPS（可选 20～60），不限制诊断录像帧率。
- **单飞识别队列与缓存**：战斗异步检测对每类识别最多保留 1 个未完成任务，慢识别时跳过追加、完成后直接取最新帧，避免旧帧排队（繁忙跳过计数见 `recognition_queue`）。角色能量/技能等小区域检查在单次角色识别后台任务内顺序批量执行；视觉流水线 YAML 按文件 `mtime_ns` 与大小缓存解析数据，音频预警模板在加载时预完成滤波与标准化。

## 常驻助手机制

勾选对应触发器后常驻观察；战斗与闪避助手不会主动把游戏切到前台，剧情助手仅在识别到可操作的剧情时激活游戏。截图中断、暂停或关闭助手时停止自动输入。

### 自动战斗助手

- **接管与续战周期**：仅看到普攻按钮不会接管；必须确认小怪血条阶梯边框（含空失衡条、低血量与半透明面板，不依赖属性图标颜色）、连续画面确认的红底黑边外指方向箭头、连携界面（含粉红/红色即将耗尽计时条）或新攻击预警后，才进入 **10 秒**战斗窗口。10 秒内不再重复检查敌人是否消失（攻击预警不延长该窗口）；到期释放按键重检，仍有敌人则开启下一轮 10 秒，否则回到「等待敌人」。
- **过场与连携隔离**：普攻按钮消失（如大招动画、交互过场）时跳过敌人、箭头、闪光与角色检测并释放按键，动画结束后在原剩余期限内恢复。连携阶段同时核对左右头像（兼容左邦布、右角色），期间只允许连携选人按键。暂停输入期间不预测切人或发布已执行状态，防止恢复后错位出招。
- **角色模板与通用回退**：优先匹配已识别编队成员以降低连携超时，存在未知头像时仍搜索全角色表。未识别角色或无匹配分支时自动回退「通用操作」（就绪时放特殊技与终结技并限制连发，普攻衔接）；也可直接在配置中选择「通用操作」。关闭「自动终结技」会跳过终结技点按与长按分支。克拉蕾与洛克茜专属模板细节见 [克拉蕾与洛克茜专属战斗模板](character-templates-claret-roxy.md)。
- **优先实时闪避（默认开启）**：黄光优先触发支援弹刀（默认空格 / 手柄 RB）并接普攻，无可用队友、切人冷却或支援不可用时回退为闪避；红光与声音提示触发闪避反击。短暂漏检一帧不会重复触发同一次弹刀，同一红光状态在实际闪避后消耗。关闭该开关时完全沿用角色原模板的应对逻辑。

### 闪避助手

- 仅持续检测红光、黄光与声音提示，无新事件时不发按键、不自动索敌或转视角。
- 持续闪光自动去重，耗时超过 **250 ms** 的过期识别丢弃；每次新事件最多开放 **0.8 秒**响应窗口执行所选模板的闪避/格挡与反击，随后释放输入。

### 自动跳过对话

- 常驻「自动跳过对话」与「委托助手」共用 `StoryDialogue`，剧情处理顺序移植自 [ZZZ OneDragon 委托助手](https://github.com/OneDragon-Anything/ZenlessZoneZero-OneDragon/blob/f6bed27f54f79c8833a66f0d7a1767721deb1e89/src/zzz_od/application/commission_assistant/commission_assistant_app.py)。
- **战斗优先**：与自动战斗同时开启时，复用战斗助手已确认的接管状态；战斗期间不启动剧情截图处理、OCR 或剧情检测，也不发送剧情点击。大招动画、连携和 10 秒战斗窗口到期后的续战复检仍保持暂停；确认不再接管或关闭自动战斗后重新识别剧情，战斗前未执行的剧情动作作废。仅启用自动战斗但尚未发现敌人时不影响剧情检测。
- **剧情模式**：选择「跳过剧情」即可同时跳过和自动点击。优先跳过、处理确认，再尝试菜单／自动；等待最多 5 秒后回到选项和正文推进。保留上游「自动点击」「等待剧情自动播放」；旧的「跳过剧情 + 自动点击」配置自动迁移为「跳过剧情」，保留首／末选项和点击间隔。
- **连续推进**：已识别的对话按配置间隔继续输入，不再用“同一句未变化”锁死。沿用上游 0.5 秒选项保护、约 2 秒未变化选项排除；已确认剧情后的过渡画面最多补点 5 次。黑幕中央字幕要求字幕外区域为黑幕且无确认按钮。「跳过剧情」先尝试右上角菜单和跳过，未出现跳过入口时推进字幕；中央字幕不参与选项识别。
- 上下有黑边、对白绘制在画面内的演出，需要同时识别到剧情控件和对白才会处理。可进入同一跳过流程，也不把演出中的文字当作选项。
- 无说话人和剧情控件的底部旁白，须同时识别到正文和对话框上、左、右描边；确认弹窗和非剧情界面不推进。
- 有说话人但无剧情控件的省略号对白，需要对话框描边和省略号；OCR 漏读时复核正文区域的等距白点，空白框不因此触发。
- **固定键鼠输入**：台词推进、菜单、跳过、确认和选项一律使用物理鼠标点击，不依赖手柄提示或手柄焦点，不使用后台窗口消息。游戏在后台时先激活窗口、等待新帧再点击，因此会切前台并移动系统光标。不会修改全局前后台选项、虚拟手柄设备或战斗键位。
- **安全边界**：先排除战斗、大世界、菜单（含角色选择）、启动页和玩法引导，再识别剧情文字与选项；邦布「系统优化」弹窗也不按剧情处理。购买、支付、消耗、充值、解锁、兑换、拆解、销毁等选项等待人工确认。只有识别到完整的跳过提示（如 `是否跳过当前剧情？` 或 `是否跳过「告别」的剧情？`）和「确认」按钮才会点击。仅在最近已核验的剧情内允许短暂过渡补点，不对未知页面持续盲点。
- 默认每 0.1 秒检测、点击间隔 0.5 秒。常驻助手丢弃超过 0.5 秒（含截图）的结果；移鼠前和按下前均复核窗口、坐标、配置、暂停及调试接管状态。光标被移离目标或触发安全角时取消本次点击，下一次重新识别；已按下的鼠标会释放。其他任务之后使用手柄时会重新同步输入模式。

## 应用任务与导航约定

任务启动后如当前停在标题画面会先自动登录；停在主菜单、地图、副本入口或特殊探索街区时，需要普通街区的任务会先逐帧核验退出或经区域九宫格传送回录像店（不凭小地图存在或按键送出即判成功）。

### 一条龙日常与进度反馈

- 侧边栏「一条龙日常」默认展开，支持勾选、拖拽或 `Ctrl+↑/↓` 调整应用顺序，点击「编辑」配置单项参数；组配置与应用选项统一保存。JSON 配置编辑器支持暂存草稿，启动任务前统一校验。
- 首页任务信息表在运行期间实时更新**当前账号、当前应用、当前步骤、步骤状态、各应用耗时与结果、进度计数**以及脱敏后的**失败画面文字**（最多 160 字，日志保留 800 字）。汇总结果逐项列出失败应用的阶段与可读原因，以及成功但需留意的提示（如电量不足提前结束）。

### 全局前置弹窗处理

每个操作节点每轮截图后都会通过 `src/navigation/popups.py` 先行检查全屏/半屏遮挡弹窗（像素特征预筛约 1 ms，未命中不跑 OCR），无论从哪个界面启动或跨每日 `04:00` 刷新弹出均可自动处理：

1. **无按钮公告弹窗**（如迷失之地内容更新）：匹配中部偏右红色关闭 `×` 且内部无操作按钮文字；后台按 B（含一次 A 兼容），前台点 `×`，最多 4 次。任务自身打开的带按钮对话框（快捷使用、兑换码等）不会被误关。
2. **月卡「今日到账 / 惊喜补给」**：橙色票面与白底预筛 + OCR 核验；后台按 B、前台点击，最多 6 次（弹窗消失后计数清零，跨 4 点再次弹出仍可关闭）。
3. **未完成活动「当前正在处理…是否继续？」**：默认选择取消（后台用左方向键将黄色焦点移至「取消」再按 A，前台直接点「取消」）；枯萎之都主动续打的「下一步」节点通过 `resumes_pending_activity` 豁免。
4. **登录阶段更新提示**：「游戏数据已更新，请重新登录。」在登录、下载及加载阶段核验正文与确定按钮后确认，重置登录状态重新进入。

### 体力刷本与恶名狩猎

- **计划表单与计数规则**：通过联动下拉配置副本类别、类型、名称、等级、卡片数、战斗模板与预备编队；修改即保存。仅真实进入战斗并核验通关胜利后计 1 次，撤退或进入失败不计次并保留原始失败原因。默认开启「每次执行重置计划次数」并关闭「循环执行」（即每次完整跑一遍计划列表）；未配置任何体力计划时明确报失败。遇到明确的特训空目标文案时跳过该条特训计划并继续后续计划。
- **专业挑战室燃竭双倍**：仅专业挑战室区分「双倍次数」与「单倍次数」（先双倍后单倍，后台用 RS 切换燃竭 ON/OFF；双倍刷完退出重进关闭燃竭）。无双倍活动且入口元素完整核验为空时，按计划的 `double_fallback` 执行：**停止**（默认）、**等体力单倍**（每 2 场单倍计 1 次双倍，`fallback_single_runs` 持久化半次进度）或**等次数单倍**（每 1 场计 1 次）。实战模拟室卡片按当前画面实际坐标双向查找；手柄后台暂不支持改卡片数，请保持「默认数量」。
- **电量读取与补充电池校验**：
  - 付费副本底部整块读取「当前电量 / 本场消耗」（实战模拟室默认卡片数读不到时按 5 张 100 点兜底；恢复弹窗遮挡时保留进弹窗前的已知消耗）。
  - 恢复电量统一归并繁简字形，核验来源标题、库存与兑换量，只使用已授权来源。确认快捷使用前必须满足 `当前电量 + 本次兑换量 >= 本场消耗`；若补完仍不够打一场，立即关闭弹窗且不扣库存（开启多来源时可尝试另一单一来源，不把两个单独都不足的来源相加）。战后「再来一次」补电不足时正常退出结算。
- **恶名狩猎**：适配新版「周期剩余时间」入口（RS 切换深度追猎、LS 选等级、X 领周期奖励，失败按画面提示撤退/退出）。**免费恶名狩猎与体力解耦**：0 电量下仍进入入口检查当期免费奖励次数，免费场次不读/不扣电量，也不触发补电；未配置狩猎计划时只领周期奖励。

### 迷失之地（含矩阵行动）

- **入口核验与完成判定**：按当前帧完整标题选择「战线肃清」「特遣调查」或「矩阵行动」，核验详情页专属控件，误入其他模式时自动退回重试。「完成悬赏委托」与「刷满周期奖励」启动时必须进入游戏入口实读「当前值/目标值」（如 `8000/8000`、`2500/2500`），不盲信本地历史标记；「刷满周期奖励」以悬赏进度满额领奖为准，不受每日/每周次数截断，也不因结算仍有丁尼而多刷。「完成周计划次数」同时受每日与每周上限约束。
- **矩阵行动后台编队**：手柄路径支持周期入口、单列预备编队选择，以及「自定义编队」（至少选 1 名主战角色，清空原主战后用左摇杆翻页、核验「代理人」标题回顶、逐槽核验头像与顺序，保留协战与邦布；角色重复、未解锁或校验失败直接停止）。协战优先选当期 UP（漏读时取首个 60 级候选）并核验右侧槽位标记。
- **准备区保护与战斗交接**：初始准备区在一切战斗识别前直接返回非战斗，直至第一层传送完成，防止误打训练木桩；已选完的武备菜单重复进入时直接关闭。寻路与进入战斗之间支持 **250 ms** 内单次遭遇证据交接，避免闪光或血条单帧闪烁丢失目标；仅在实际启动自动战斗后重置 50 次无目标转向上限。

### 快捷导航与随便观

- **地图快捷导航**：无图标模板或后台传送统一经地图菜单键（≡）打开「快捷导航」（要求网格内至少识别出 3 个已知地图区域名，防止与丽都周纪九宫格混淆），核验区域焦点与底部地点焦点后传送；区域确认若被模式切换吞掉会自动右移重立焦点（最多 3 次）。
- **随便观后台流程**：关闭经营日志并推进有限步数的新手引导；读取「经营方针」（X）自动托管状态，未满 Lv.35 时按黄色边框与 LB/RB 页签依次执行：游历收获与派遣（取不超过配置的最长可用时长，从不按「提前收获」）、饮茶仙「定期采办」（不提交消耗收集物的「邻里心愿」）、制造坊一键收获与首个可制造品开工、售卖铺 RS 拾遗。

## 可观测性与诊断工具

### 画面与日志诊断录制

在「调试 → 🛠️ 画面与日志诊断」选择「截图」「视频」或「截图和视频」开始录制（默认不限时，可选 480P/720P/1080P 与 5～60 FPS，独立于 F9 任务暂停，不发游戏输入、不录音频）。停止或到时后在 `debug/diagnostics/<日期时间>/` 生成目录与同名 ZIP：

- `frames/` 与 `frames.jsonl`：自动遮挡 UID 的截图（单次最多保留 300 张）及辅助特征、窗口与任务状态。
- `video.mp4`（不支持时为 AVI）与 `video-timeline.jsonl`：约 1 GB 自动分段，`capture_age` 记录帧龄，取帧中断超 2 秒标记 `NO FRESH GAME FRAME`。
- `events.jsonl`：敌人面板 `enemy_panel`、战斗触发、副本节点、闪避/对话识别及程序 `input_call`。
- `user-input.jsonl`：仅游戏处于前台且鼠标在客户区内时记录键鼠事件，区分物理输入、程序 `input_call` 与系统 `observed_injected_input`。
- `logs/` 与 `session.json`：运行日志片段、停止原因与丢弃统计。`elapsed` 不含录制暂停时长，`wall_elapsed` 含暂停时长。

### 阶段超时检测

「全局设置 → 阶段超时检测」默认开启（阈值默认 300 秒，范围 30～7200 秒；自动打包默认关闭）。独立低频监控线程在操作节点停留超时后（即使执行线程阻塞也能触发，同一节点只报一次）：

1. 在 `debug/stalls/<时间>/` 保存脱敏后的运行状态快照、全线程调用栈与最近日志（含 `runtime.log`）。
2. 发送带当前画面的程序错误通知，并尝试启动 60 秒诊断录制（已有录制时不打断）。
3. 开启自动打包时生成与「发送错误报告」一致的 ZIP。监控**只记录与通知，不会自动停止任务或向游戏发送输入**。

### 实时调试与游戏控制

「调试 → 实时调试与控制」默认关闭；开启后在 `127.0.0.1` 随机端口提供 Bearer Token 认证接口（凭据位于运行目录 `debug/live/session.json`，退出删除），支持只读查看 `/status`、`/events`、`/threads`、`/frame.jpg`、`/frame.png`，以及租约式后台接管（释放时自动还原账号原控制器映射）和 `stop_before` 节点前安全演练。CLI 与接口参数详见 [实时调试与游戏控制](live-debug.md)。

## 系统兼容与已知风险

- **管理员权限匹配**：启动 `ok-zzz` 默认不要求管理员权限；但若《绝区零》以管理员身份运行，Windows UIPI 会拦截普通权限进程发出的窗口消息与输入，`ok-zzz` 也必须以管理员身份运行。
- **ViGEmBus 驱动蓝屏风险**：上游 ViGEmBus `1.21.442` 已停止维护，存在客户端异常断开或开关机阶段的内核空指针缺陷（BSOD `0x50`）。`ok-zzz` 仅在实际使用后台手柄时连接驱动，并在正常退出或系统注销/关机时主动移除虚拟手柄——**请勿用任务管理器强杀 `ok-zzz` 进程**。UU 远程、MuMu 远程、Parsec 等常驻连接 ViGEmBus 的软件在不用手柄功能时建议关闭开机自启。
- **杀毒软件误报启动器**：安装目录下的原生启动器 `ok-zzz.exe` 可能被 Windows Defender 误报隔离（常见签名 `Trojan:Win32/Bearfoos.A!ml`），表现为检查更新提示未找到启动器；恢复文件并将安装目录加入安全中心排除项即可。

## 开发、测试与发布打包

### 本地开发与测试

需要 Python 3.12（用户运行锁文件与开发工具分层维护，仓库卫生测试会强制校验）：

```powershell
# 1. 创建虚拟环境并安装锁定运行依赖 + 开发测试依赖
uv venv --python 3.12 .venv
.venv\Scripts\activate
pip install --no-deps -r requirements.lock.txt
pip install -r requirements-dev.txt

# 2. 启动界面
python main.py          # 正常运行
python main_debug.py    # 调试模式（绘制识别框）

# 3. 离线验证（测试自动在临时目录副本上隔离运行，不改动仓库内配置）
python -m pytest tests/ -q
python main.py --check-package          # 离线自检依赖、资源、UI 控件、DML/CPU 模型推理与迷失之地状态机
python tools/gen_app_tasks.py --check   # 校验生成的任务选项文件无漂移
```

### 正式发布流程（PyAppify）

线上发布由 `.github/workflows/build.yml` 自动完成，推送正式版标签 `vX.Y.Z` 前需确保 `src/config.py` 与 `pyproject.toml` 中的 `version`（无 `v` 前缀）与标签一致：

1. **Run tests**：安装 ViGEmBus、锁定依赖与开发依赖，运行全量离线回归。
2. **Synchronize update repository**：按 `deploy.txt` 与 `.update_repo_gitignore` 将运行时代码与资源同步到 `ok-zzz-update` 仓库并打标签（启动器在线更新从此拉取，工作目录位于 `<安装目录>/data/apps/ok-zzz/working`）。
3. **Build launcher and installers**：先运行 `tools/launcher/build.ps1` 编译带超时与日志级别补丁的固定版本 PyAppify 1.2.3 原生启动器，再打包生成 `ok-zzz-win32-Global-setup.exe`、`ok-zzz-win32-online-setup.exe`、`ok-zzz-win32.zip` 与 `win32_sha256.txt`。
4. **Publish GitHub release**：上传安装包并附带标签间更新日志。注意：在线更新只替换 `working/` 下的 Python 工作目录，原生启动器 `ok-zzz.exe` 本身的改动需覆盖启动器或运行新版安装包生效。

### 可选：离线独立打包（PyInstaller / NSIS）

`deploy/` 保留了旧版单机冻结打包配置，仅供无 PyAppify 环境手工验证（冻结版运行目录位于 `%LOCALAPPDATA%/ok-zzz`，不含在线更新服务）：

```powershell
python -m PyInstaller --noconfirm deploy/ok-zzz.spec
& ./dist/ok-zzz/ok-zzz.exe --check-package
makensis /DAPP_VERSION=0.2.15 /DBUILD_TAG=v0.2.15 "%CD%\deploy\ok-zzz.nsi"
```
