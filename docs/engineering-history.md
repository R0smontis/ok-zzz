## 性能优化与基准测量

> 说明：离线局部基准测量的是固定输入和固定识别频率下的单路径 CPU/墙钟耗时，不能直接换算或相加为整场战斗、整个进程或整机的 CPU 降幅。

### 2026-10-08 血条检测与调试预览降耗

- **改动**：血条检测在同一帧内复用轮廓；最佳模板匹配直接选择最高分；调试页隐藏或窗口最小化时跳过界面预览编解码，重新显示后恢复最新预览；移除截图编码前的重复 1080P 缩放。后台监控、HTTP 截图、识别帧率、阈值、角色候选及模板优先级不变。
- **离线验证**：26 张本地截图的血条/方向箭头检测返回值与修改前一致，PNG/JPEG 输出字节一致。同机回放血条检测 CPU 耗时约减少 7.7%，密集命中的最佳匹配样例约减少 86%（仅代表局部路径，游戏内总占用仍取决于整场负载）。

### 2026-10-24 启动耗时优化

主线程从解释器启动到主窗口显示由约 6.5 秒降至约 5.4 秒（三次取中位数，测量脚本在显示主窗口时退出）：

- **延迟导入 `scipy`**：启动时不再导入 `scipy`（原先加载 534 个模块，约 1 秒）。闪避声音滤波、互相关、重采样，小地图朝向峰值检测，以及质心距离过滤改为首次使用时导入；声音模板仍在战斗开始时由后台线程加载。
- **延后安装战斗开关**：自动战斗助手注册「优先实时闪避」开关时不再在界面线程提前构建 `ZzzContext`（原约 0.45 秒），改为通过 `Globals.when_context_ready` 在上下文创建时安装，仍实时读取配置。
- **未改动部分**：其余耗时主要在框架界面构建（`MainWindow` 约 3.8 秒，其中状态栏样式表约 0.8 秒、任务卡片约 1 秒），属 `ok-script` 与 `qfluentwidgets` 内部实现。启动器检查更新后的 10 秒自动启动等待用于留出取消时间，保持不变。

### 2026-11-12 战斗轮次等待与视觉流水线缓存

- **按轮补时替代固定睡眠**：实战模拟室、专业挑战室、恶名狩猎、区域巡防、战斗操作基类、零号空洞、情报板、式舆防卫战和大世界巡逻共 11 处识别循环改用 `round_wait(wait_round_time=...)`。截图与同步识别耗时计入轮次间隔，只补足剩余时间，不在识别后再固定睡眠 20 ms。截图入口仍受「识别帧率上限」（默认 30 FPS）控制；移动后等待、非战斗导航等待及各检测器自身间隔不变。
- **缓存视觉流水线 YAML**：`CvService.load_pipeline` 按文件路径缓存 YAML 解析数据，以 `st_mtime_ns` 和文件大小判断外部修改。每次加载仍创建独立流水线与步骤并复制配置；保存、重命名、删除使缓存失效，文件消失或解析失败时不复用旧结果。缓存不保存截图、上下文或识别结果。
- **离线测量**（`combat_recording/battle_169.jpg`，2560×1440 BGRA 输入视图，OpenCV 2 线程；单项 200 次，模拟战斗循环 300 轮）：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 目标检测 `run_all_checks` 中位耗时 | 1.970 ms | 1.679 ms |
| 目标检测 p95 | 2.317 ms | 1.920 ms |
| 轮末等待中位耗时 | 20.41 ms | 0.0013 ms |
| 模拟循环整轮中位间隔 | 30.99 ms | 28.05 ms |
| 模拟循环整轮 p90 | 46.04 ms | 42.02 ms |
| 模拟循环平均帧率 | 30.0 FPS | 29.7 FPS |

目标检测中位耗时减少约 15%。现成帧离线循环原本已达帧率上限，修改后等待转移到截图入口限速处，不能据此声称吞吐提升；忙碌跳过次数也未呈稳定下降。`combat_recording` 全部 26 张图像的 `lock-far` 流水线输出逐项一致，全量回归 1796 通过、2 跳过。

- **单场实战观测**（WGC 后端，「实战模拟室·风切测试」单场）：采集 1134 条「攻击 HUD 可见且自动战斗运行中」事件（剔除 ≥500 ms 的画面切换间隔），相邻事件间隔中位数 **35.50 ms**、p90 **44.66 ms**、p95 **51.34 ms**；目标检测无忙碌跳过，角色检测忙碌跳过 91 次、快速支援 72 次。此前 55.8 ms 记录来自 `BitBlt_True`，两者后端不同，不能将差值全部归因于轮次优化。

### 2026-11-13 模型预处理、角色状态与截图通道降耗

在不降低识别帧率、不增加等待、不削减检测项、不改匹配阈值和按键时序的前提下，分两轮减少临时分配、复制与小任务调度开销（基线已含按轮补时与流水线 YAML 缓存）：

1. **第一轮（推理输入、敌人面板与角色状态调度）**
   - `onnx_utils.scale_input_image_u`：OpenCV 直接将缩放结果写入 letterbox 目标区域（保留非 `uint8` 兼容路径），数值与 CHW 布局不变。把类型转换与 `float32` 除法合并为单次 NumPy 操作的试验更慢（0.703 ms → 0.813 ms），未采用。
   - `battle_presence._find_world_panel`：单次调用内按候选高度复用筛选后的模板列表，无适用模板时跳过图像准备；跨帧不缓存。
   - `AutoBattleAgentContext._check_agent_states`：角色能量、技能等小区域检测在已有角色识别后台任务内顺序执行，不再逐项提交 Future；头像匹配仍并行，单飞队列与逐项异常隔离不变。
2. **第二轮（截图原地遮挡与颜色通道视图）**
   - `ZzzController.screenshot`：在 `normalize_bgr` 生成的独占 RGB 缓冲区上原地遮挡 UID（`(114, 114, 114)`），不再整图复制；`ZPcController.fill_uid_black` 默认仍复制输入，仅明确独占图像的入口传 `new_image=False`。将 BGRA 缩放移到颜色转换之前的试验更慢且上采样有像素差异，未合入。
   - 角色颜色通道判定用两次 `np.maximum` 直接读取通道视图，替代 `cv2.split` 与堆叠归约，保留阈值、膨胀、连通块面积与浮点 `NaN` 不命中的语义。

**局部 CPU 测量**（同一进程交替执行优化前后实现，OpenCV 2 线程，统计 `time.process_time()` 累计所有线程 CPU 毫秒，7 批取中位数）：

| 检查范围 | 修改前 CPU ms/次 | 修改后 CPU ms/次 | 局部降幅 |
| --- | ---: | ---: | ---: |
| 完整角色识别：洛克茜、丽娜、克拉蕾 | 7.45 | 7.08 | 约 4.9% |
| 三人队的能量/技能等状态子步骤 | 1.56 | 0.50 | 约 68% |
| 状态较多的三人队：叶瞬光、仪玄、简 | 2.56 | 1.13 | 约 56% |
| 混合敌人扫描（27 张正例、负例和特效画面） | 28.07 | 26.84 | 约 4.4% |
| 1920×1080 → 640×640 模型预处理 | 1.34 | 1.33 | 约 1%（接近波动范围） |
| 实际 `screenshot` 归一化及 UID 遮挡路径 | 12.000 | 11.375 | 约 5.2% |
| 单项角色颜色通道检查 | 0.01302 | 0.01042 | 约 20%（绝对值仅数微秒） |

等价性核验覆盖 216 组模型预处理、54 张敌人/场景画面、164 组角色状态（含 60 名已登记角色专属状态）、52 组实际截图逐像素对照及 78 组颜色通道对照，输出完全一致；全量回归 1865 通过、2 跳过。

### 2026-11-13 同设置实战 CPU 对照（VR 训练场）

- **实验条件**：免费 VR 训练场，固定编队（60 级克拉蕾、洛克茜、丽娜），10 级提尔锋开启敌人无敌、行动与失衡，关闭角色无限资源。后台 Xbox 手柄、WGC、2560×1440 原始画面（1920×1080 逻辑画面）、RTX 5080 DirectML、CPU 2 线程。A 组仅将 7 个 CPU 实现文件恢复为 `e6d71990` 基线，B 组使用优化实现；按 `B1 → A1 → A2 → B2` 顺序执行，每轮激活战斗后预热 15 秒，采样约 60 秒。CPU 按 16 逻辑核归一化助手 GUI 进程全线程用户态+内核态时间，识别帧数取 `flash` 提交计数增量。

| 轮次 | 有效窗口秒数 | 助手进程平均 CPU | 有效识别 FPS | CPU ms/识别提交帧 |
| --- | ---: | ---: | ---: | ---: |
| B1 优化实现 | 59.792 | 6.412% | 25.355 | 40.464 |
| A1 基线实现 | 60.792 | 6.392% | 25.151 | 40.662 |
| A2 基线实现 | 59.852 | 6.495% | 24.661 | 42.143 |
| B2 优化实现 | 59.880 | 6.411% | 25.384 | 40.409 |
| A 合计归一化 | 120.644 | 6.443% | 24.908 | 41.389 |
| B 合计归一化 | 119.672 | 6.412% | 25.369 | 40.437 |

- **结论与边界**：样本内进程 CPU 相对减少约 0.49%，单位识别提交帧 CPU 时间减少约 2.30%，有效识别吞吐增加约 1.85%。差异小于基线两轮间的自然波动——**整程序 CPU 基本持平，未观察到明显升高，也不能据此宣称稳定、显著的整程序 CPU 降耗**。训练场敌人 AI 与动画非确定性，每组仅两轮，不证明所有场景逐帧等价。

### 2026-11-13 声音预警模板预处理复用

- **改动**：固定音频模板在加载阶段完成滤波与标准化，后续相关性检测复用只读结果；完整构造后再发布 `_audio_template`，失败可重试。实时音频滤波、FFT 相关性、阈值和检测周期不变；其他模板仍现场标准化。仅对最大值做除法的候选无稳定收益，未采用。
- **测量与验证**：19734 样本模板与 16000 样本确定性噪声，交替 9 批×2000 次，单次 CPU 中位数 `1.03125 ms → 0.96875 ms`（约 6.1%，绝对收益约 0.0625 ms，不代表整程序降 6%）。相关性结果与旧实现完全相等，相关回归 121 项通过。
